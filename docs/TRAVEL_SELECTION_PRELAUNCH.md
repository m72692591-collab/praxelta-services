# ПРАКСЕЛЬТА · подбор поездки

Дата фиксации: 18 августа 2026 года. Статус: **PRELAUNCH**.

## Назначение

Направление предоставляет информационный подбор до трёх вариантов поездки по восьми безопасным параметрам. Публичная ветка содержит только статические страницы и границы продукта.

Закрытый рабочий контур находится в локальном `praxelta-ops` и не публикуется в этом репозитории. В нём подготовлены SQLite, Telegram long polling, ранжирование, импорт официальных JSON/CSV-фидов, агрегированная локальная панель, удаление данных, suppression, журналы проверок и блокировка рекламы без ERID.

В режиме `PRELAUNCH` или `PRIVATE_TEST` Telegram-контур отвечает только ID владельца из локального allowlist и не создаёт записи посторонних пользователей. Также подготовлены read-only Finance API и Links API Travelpayouts: токен хранится только локально, ссылки создаются как `DRAFT_NOT_PUBLISHED` и не отправляются автоматически.

## Почему production не имитируется

Регистрация партнёрского аккаунта означает принятие условий владельцем. Токен BotFather, OTP, API-ключи, платёжные сведения и юридические реквизиты не создаются mock-данными и не публикуются в GitHub.

## Обязательная граница

ПРАКСЕЛЬТА не принимает деньги туриста, не получает паспортные и платёжные данные, не заключает договор туристского продукта, не бронирует от своего имени и не принимает претензию вместо продавца.

Партнёрская ссылка публикуется только после проверки источника трафика, рекламной маркировки, действующего ERID, сведений о рекламодателе и окончательной правовой редакции страниц.

## Критерий production

Production возможен только когда одновременно:

1. владелец лично принял действующие условия партнёрской платформы;
2. создан проект и получены действующие инструменты;
3. импортированы реальные официальные предложения;
4. указан оператор персональных данных и проверена обязанность уведомления Роскомнадзора;
5. утверждены политика, согласие, условия и партнёрское раскрытие;
6. приватный тест Telegram подтверждён `message_id`;
7. `doctor`, unit-тесты, preflight и отрицательные gate-тесты имеют статус PASS;
8. отдельным решением включён `PUBLIC_DEPLOY`.
