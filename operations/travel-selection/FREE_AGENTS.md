# ПРАКСЕЛЬТА Travel: бесплатные агенты

Статус: **ZERO_BUDGET_PRELAUNCH**.

Этот контур использует бесплатные GitHub-hosted runners публичного репозитория и стандартную библиотеку Python. Платные API, токены нейросетей и рекламный бюджет не требуются.

## Состав

### Маэстро

Запускает остальные проверки, собирает один `status.json`, один человеческий отчёт и следующий безопасный шаг.

### Монитор витрины

Проверяет публичные страницы GitHub Pages. Сетевой сбой помечается как `WARN`, но не выключает локальные safety-gates.

### Контур безопасности

Проверяет:

- наличие CSP `connect-src 'none'` и `form-action 'none'`;
- отсутствие `fetch`, XHR, WebSocket, storage и cookies в travel-JavaScript;
- отсутствие секретоподобных значений и приватных ключей;
- отсутствие небезопасной HTML-вставки;
- наличие юридических страниц и канонического бренда.

### Контент-агент

Каждый день выбирает один материал из `travel-pilot-content-pack.json` и создаёт артефакт `daily-content-draft.md`.

Статус всегда `DRAFT_NO_SEND`. Агент не публикует материал и не считает черновик рекламой без отдельной классификации.

### Контролёр коммерческой готовности

Проверяет только наличие внешних gates и состояние аварийных переключателей. Значения секретов в отчёт не попадают.

До отдельного production-review должны оставаться выключенными:

- `PUBLIC_BOT`;
- `REAL_SEND`;
- `REAL_MONEY`;
- `REAL_LEAD_TRANSFER`;
- `AD_SPEND`;
- `ALLOW_EXTERNAL_LINKS`.

## Расписание

Workflow `.github/workflows/travel-free-agents.yml` запускается:

- ежедневно;
- вручную;
- после изменений travel-витрины, content pack, агентов или их политики.

Результаты сохраняются как GitHub Actions artifact. Один GitHub issue с заголовком `[FREE AGENTS STATUS] ПРАКСЕЛЬТА Travel` создаётся или обновляется автоматически, поэтому ежедневные проверки не создают новые дубли.

## Что агенты не делают

- не регистрируют аккаунты;
- не принимают пользовательские соглашения и оферты;
- не проходят OTP и CAPTCHA;
- не создают Telegram-токен;
- не публикуют посты;
- не отправляют холодные сообщения;
- не расходуют деньги;
- не собирают клиентские данные;
- не включают реальные партнёрские ссылки;
- не подменяют налоговое или юридическое решение владельца.

## Артефакты каждого запуска

- `status.json` — машиночитаемый статус;
- `status.md` — единый человеческий отчёт;
- `daily-content-draft.md` — один безопасный черновик дня.

## Критерий отказа

Workflow становится красным только при критическом нарушении: отсутствующем обязательном файле, сетевом side effect в браузерном коде, найденном секрете, повреждённом content pack или включённом опасном production-переключателе.
